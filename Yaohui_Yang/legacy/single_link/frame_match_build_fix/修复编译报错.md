# 修复 esp_lcd_panel_rgb.c 编译器崩溃

截图中的错误为：

```text
during RTL pass: ira
esp_lcd_panel_rgb.c: In function 'rgb_panel_draw_bitmap':
internal compiler error: Segmentation fault
```

它发生在电脑编译ESP-IDF自带LCD驱动时。截图不足以确认编译器内部崩溃的具体原因。
目前工程没有使用LCD，却默认把整个ESP-IDF组件集合加入构建，因而触发了这个文件的编译。
这次改为只构建main和明确声明的直接/间接依赖，绕过这条与测距无关的编译路径。
这是针对已观察到报错点的工程级绕过，不能保证解决其他文件中的工具链崩溃。

## 修改内容

Anchor与Tag的顶层CMakeLists.txt都增加以下配置，位置在include(project.cmake)之前：

```cmake
cmake_minimum_required(VERSION 3.22)
set(COMPONENTS main)
include($ENV{IDF_PATH}/tools/cmake/project.cmake)
project(qar_ftm_anchor)
```

Tag最后一行使用`project(qar_ftm_tag)`。
main/CMakeLists.txt已明确声明Wi-Fi、网络、事件、NVS、计时器等所需依赖，ESP-IDF会自动补齐传递依赖。
修复包没有修改Anchor/Tag的C源码、无线参数、CSI格式和电脑端CIR模型。
两个烧录脚本也已更新：新目录首次设置目标，已有sdkconfig时只重新配置，避免每次重试都清空整个构建。

## 现在就能执行，不必重新下载也能临时应用

在已激活ESP-IDF v6.0.2的PowerShell中，关闭占用串口的程序，然后执行：

```powershell
cd C:\\Users\\YOUR_USER\Desktop\QAR_FTM_S3_CIR_FIT\anchor
idf.py -DCOMPONENTS=main reconfigure
idf.py build
idf.py -p COM4 flash monitor
```

COM4取自这次Anchor截图；如果设备管理器显示其他端口，使用实际编号。
每条命令成功后再执行下一条。不要在前一步编译失败后把串口输出当作新固件验证。
这条`-D`命令把构建范围写入当前构建目录的CMake配置；更新包内的CMakeLists则使新建构建也默认采用该范围。

若使用的是刚解压的新目录，先执行一次`idf.py set-target esp32s3`，再运行上述重新配置、编译和烧录命令。
既有sdkconfig已经是esp32s3时无需重复set-target。仅调整组件范围不需要擦除整块Flash。

编译通过并退出Anchor监视后，再在Tag子工程同样操作：

```powershell
cd C:\\Users\\YOUR_USER\Desktop\QAR_FTM_S3_CIR_FIT\tag
idf.py -DCOMPONENTS=main reconfigure
idf.py build
idf.py -p COM12 flash monitor
```

COM12沿用之前的Tag端口，使用前核对当前编号。新解压Tag目录同样需要先设置一次目标。

## 检查是否生效

重新配置后，可在当前子工程执行：

```powershell
Select-String -Path .\build\compile_commands.json -Pattern 'esp_lcd_panel_rgb.c'
```

正常应无匹配输出，表示这次构建不再编译该文件。编译总步数会随配置变化，不用对照固定数量。
如果仍有匹配，请检查当前目录、命令是否成功，以及是否确实使用此修复包中的CMakeLists.txt。

截图后一次运行已经显示`Hash of data verified`，说明当次写入并校验成功，早先编译失败没有阻止那次后续烧录。
要确认应用运行，还需要看到`ANCHOR_READY`或Tag的数据输出。
缺少应用日志是另一个排查点：本工程默认将应用日志输出到原生USB Serial/JTAG，UART烧录口可能只能看到ROM日志。
先核对实际USB接口和串口，不因看不到日志而反复全量清理编译。

## 若其他文件仍出现 internal compiler error

这时需要继续检查电脑工具链。保留第一条错误及其前面的完整编译命令，并记录：

```powershell
idf.py --version
xtensa-esp32s3-elf-gcc --version
```

当前环境没有ESP-IDF、Xtensa交叉编译器和实体板卡，未声称完成本次修复的Windows编译或硬件验证。
最终以你的`idf.py build`及板卡运行结果为准。
