# 多距离采集与 CIR 拟合

增加不同距离的数据是下一步，但同一距离也要换摆放位置重新采集。
之前的模型使用1、2、3m三组训练，独立测试只有一组2m；单点测试无法区分“学到了距离”和“总输出接近2m”。
本流程沿用现有V5同帧CSI采集，在电脑端提取CIR特征并拟合距离，不需要换成Wi-PRO版本。

## 建议先完成这一轮

| 数据组 | 实际摆放位置 | 距离 | 每点时长 | 用途 |
|---|---|---|---|---|
| 训练 | A，允许复用已有V5训练记录 | 1、2、3、4、6、9m | 120秒 | 拟合参数 |
| 验证 | B，整套设备换到新的位置 | 1、2、3、4、6、9m | 120秒 | 选择正则化强度 |
| 最终测试 | C，再换一个未用的位置 | 1、2、3、4、6、9m，再加1.5、2.5、5m | 120秒 | 检查新位置和未训练距离 |

共21组。复用包内已有的1、2、3m训练记录后，新采18组，纯记录约36分钟；搬设备和量距离另计。
不复用则新采21组，纯记录约42分钟。两分钟不是精度保证，是便于获得多轮稳定记录的起点。

“不同位置”是实际挪动设备、改变它们相对房间和反射物的位置；仅重新开始文件或改试验名不算。
A/B/C可以在一个足够大的房间内选择不同区域，当前结果也就只适用于这样的验证范围。
如果要判断换房间是否有效，让C位于另一个房间。先全做无遮挡LOS；遮人、穿墙另建实验，不与本轮混合。

每次采集注意：

1. 用卷尺量天线之间的实际距离，尽量控制到厘米；不使用FTM显示值作为标签。
2. 固定两块板的高度、姿态和天线朝向，例如都放在约1.2m高的非金属支架上。
3. 保持视线无遮挡，记录期间设备静止；操作人员离开两块板之间的路径。
4. 保持同一对设备、固件、信道、带宽和发射设置，关闭占用Tag串口的monitor。
5. 每组开始前按脚本提示摆放。实际只有1.98m时输入`1.98`，不要为了凑2m标签而按回车。

已有记录只有在设备和采集配置兼容时才适合复用。如果已经换板、换天线或改了采集设置，请不加`--reuse-existing`，把A也重新测完。
本脚本只导入包内三组V5同帧记录；更早的HT/UDP时间窗CSI不能直接混入这次同帧模型。

## 一条命令完成采集、拟合和测试

Tag已运行当前V5固件时，无需重新编译或烧录。Anchor保持供电，Tag连COM12。
将包解压到桌面，在普通Windows PowerShell执行：

```powershell
cd C:\\Users\\YOUR_USER\Desktop\QAR_FTM_S3_CIR_FIT
python -m pip install -r .\requirements.txt
python .\tools\cir_experiment.py wizard --port COM12 --reuse-existing --extra-test-distances 1.5 2.5 5
```

也可以在安装依赖后运行：

```powershell
.\run_multidistance_COM12.ps1
```

路径或串口不同就修改对应部分。脚本会按训练、验证、最终测试三个阶段进行，每个阶段内部打乱距离顺序。
提示中的`train / validation / test`分别是训练A、验证B、测试C。开始B、C前实际移动设备。

```text
Set antenna spacing to 4m at A. Enter=start, number=actual measured meters, s=skip, q=stop:
```

- 直接回车：记录的真实距离就是提示的标称距离。
- 输入数字：使用卷尺实际量得的米数作为标签，然后开始采集。
- `s`：暂时跳过这个点，该阶段不会被当作已完成。
- `q`：退出；下次执行相同命令，会跳过已完成的采集并继续剩余部分。

记录提前中断或可用数据少于10个会话时，会保留文件并要求重采，不覆盖上一次尝试。
每个有效会话还需要至少4个可用FTM同帧CIR。这个检查只说明数据够处理，不说明已经达到某种精度。
在提示处用`q`停止最方便；采集期间用`Ctrl+C`停止，未满时长的部分通常会按未完成处理。

首次运行才能设置距离和时长。之后相同命令会沿用`experiment.json`中的原计划。
若场地只能到6m，可在第一次运行时改为：

```powershell
python .\tools\cir_experiment.py wizard --root .\experiments\LOS_6M --port COM12 --reuse-existing --distances 1 2 3 4 6 --extra-test-distances 1.5 2.5 5
```

更改`--root`会新建另一轮实验，不会覆盖上一轮。后续操作同一实验都要传入相同的`--root`。

## 拟合算法与隔离方式

处理链沿用现有代码：

`FTM同帧CSI → 20MHz LLTF频点 → 缺失频点重建 → 插值CIR → 相对CIR特征 → 距离回归`

主模型`cir_direct`只用CIR形状和CSI频率选择性特征拟合距离；训练目标是卷尺标签。
它学习的是特征与距离的统计关系，没有把未经绝对时延标定的CIR峰值位置直接当成传播距离。
插值增加曲线采样密度，不会增加实际信号带宽。

模型为带正则化的线性回归。缩放参数只由A计算，每个完整采集的总训练权重相同，
避免某组记录较长就主导模型。另保留两条对照算法：只用FTM的线性校准`ftm_affine`，
以及CIR和FTM共同拟合修正量的`cir_residual`。这些算法都使用当前V5数据。

1. 只用A拟合，使用B的“各采集MAE等权平均”从`alpha=1、10、100`中选参。
2. 模型仍只用A拟合，不再把B并入训练。保存模型哈希并冻结后，才开始收集C。
3. C只算误差，测试入口不重新训练；评估前验证模型未被修改。
4. 同一完整采集不跨组，程序检查采集内容指纹，不能复制一组数据改名当作独立测试。
5. 不根据测试结果裁剪预测范围或丢掉域外/负数预测；无法提取CIR的会话另报覆盖率。

同一采集里的数千帧具有相关性，不要随机拆帧当训练集和测试集。
如果看过C的误差后又改模型，C就已经成为开发数据；下一次最终结论需要新的独立测试采集。
这一轮是检验方法是否值得继续的起点。若换到C后明显变差，优先补不同位置的训练采集，再建新一轮验证。

## 输出与判断方法

默认实验保存在`experiments/LOS_MULTI/`：

| 文件 | 内容 |
|---|---|
| `experiment.json` | 点位计划、真实距离、完成状态和采集路径 |
| `captures/` | 全部原始串口日志、CSI、FTM、元数据；失败尝试也保留 |
| `fit/models/` | 本轮冻结的新模型 |
| `fit/candidate_validation_scores.csv` | 各候选参数的B组误差 |
| `fit/selection.json` | 所选参数、模型哈希和训练/验证审核 |
| `fit/final_report.md` | C组最终误差及可用会话比例 |
| `fit/test_by_distance.csv` | 每个实际距离分别的MAE、RMSE、P90等 |
| `fit/test_predictions.csv` | C组每轮的预测、真实距离和质量状态 |

首先看C组的`cir_direct`是否在多数距离上稳定，以及1.5、2.5、5m是否正常。
同时比较原始FTM、FTM线性校准和“总输出训练标签均值”的基线。
如果CIR只在训练A上误差小，或不如简单FTM校准，就不能据此声称CIR测距已改善。
除了平均误差，还要看P90、大误差距离、域外次数、可用会话比例。
不要只报告某个距离最好的几次结果。

包内根目录`models/`和`results/`是旧1/2/3m实验的模型与历史结果；新一轮不会覆盖它们。
新增18组尚未实际采集，包里没有它们的测距结果，也没有预先保证的分米级精度。

## 使用新模型实时测距

完成向导后使用本轮模型路径：

```powershell
python .\tools\cir_distance.py live --port COM12 --models .\experiments\LOS_MULTI\fit\models
```

实时预测不需要输入真实距离。`DISTANCE`为拟合距离，`RAW_FTM`为原始FTM，CSV保留所有模型和质量状态。
`OUT_OF_DOMAIN`表示特征明显偏离训练分布，不能当作可靠距离；它也不是经过标定的误差概率。
若使用了自定义`--root`，这里同步改成该实验的`fit/models`路径。

## 分步运行、查看进度和打包

不想连续完成三个阶段，可以按以下顺序运行：

```powershell
python .\tools\cir_experiment.py init --reuse-existing --extra-test-distances 1.5 2.5 5
python .\tools\cir_experiment.py collect --split train --port COM12
python .\tools\cir_experiment.py collect --split validation --port COM12
python .\tools\cir_experiment.py fit
python .\tools\cir_experiment.py collect --split test --port COM12
python .\tools\cir_experiment.py evaluate
```

向导已经初始化过时，不要再次运行`init`；直接继续`wizard`或相应的`collect`。
查看完成情况：

```powershell
python .\tools\cir_experiment.py status
```

采完或中途需要检查时，打包整轮数据与报告：

```powershell
python .\tools\cir_experiment.py export --out .\LOS_MULTI_dataset.zip
```

把这个ZIP发来，就能核对原始数据、按距离看误差和决定下一轮补哪些位置。
导出不会覆盖同名ZIP，再次导出请换一个文件名。
