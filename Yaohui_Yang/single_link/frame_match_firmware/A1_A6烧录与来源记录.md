# A1–A6 编号与烧录

## 本次功能

六块固定板分别烧录 A1、A2、A3、A4、A5、A6。它们广播不同 SSID：

| 固定板编号 | SSID | 无线设置 |
|---|---|---|
| A1 | RTT_CIR_A1 | 信道 6、20 MHz、FTM offset=0 |
| A2 | RTT_CIR_A2 | 信道 6、20 MHz、FTM offset=0 |
| A3 | RTT_CIR_A3 | 信道 6、20 MHz、FTM offset=0 |
| A4 | RTT_CIR_A4 | 信道 6、20 MHz、FTM offset=0 |
| A5 | RTT_CIR_A5 | 信道 6、20 MHz、FTM offset=0 |
| A6 | RTT_CIR_A6 | 信道 6、20 MHz、FTM offset=0 |

保留每块板的真实 AP MAC/BSSID，不克隆 MAC。编号用于人工识别，实际来源同时以 BSSID 记录。
AP MAC 与 STA MAC 可能不同；登记的是 ANCHOR_READY 中的 bssid 字段。
这些编号尚未对应任何已知实物板；须逐块烧录、贴标签并记录。

## 烧录固定板

在 ESP-IDF v6.0.2 PowerShell 中，进入解压得到的 QAR_FTM_S3_CIR_FIT 文件夹。
每次接一块待烧录固定板的 UART/CP210x 接口，设备管理器确认它的 COM 号。
TAG 的 COM11 不代表固定板也使用 COM11。

```powershell
cd C:\\Users\\YOUR_USER\Desktop\QAR_FTM_S3_CIR_FIT
$anchorPort = Read-Host '输入当前这块固定板的 UART 端口，例如 COM4'
python .\tools\flash_numbered.py --role anchor --id A1 --port $anchorPort
```

这条命令会编译并烧录 A1，然后打开监视器。看到类似下面的输出后，把这块板贴上 A1 标签：

```text
ANCHOR_READY,anchor_id=A1,ssid=RTT_CIR_A1,channel=6,bssid=该板实际MAC,ip=192.168.4.1
RADIO_ANCHOR,requested_ht40=0,reported_bw_mhz=20,primary=6,secondary=0,ftm_offset_cm=0
```

把实际 bssid 记入 anchors_A1_A6.csv 的 A1 行。按 Ctrl+] 退出监视器。
换下一块固定板，重新确认它的端口，依次执行：

```powershell
$anchorPort = Read-Host '输入 A2 固定板的 UART 端口'
python .\tools\flash_numbered.py --role anchor --id A2 --port $anchorPort
```

```powershell
$anchorPort = Read-Host '输入 A3 固定板的 UART 端口'
python .\tools\flash_numbered.py --role anchor --id A3 --port $anchorPort
```

```powershell
$anchorPort = Read-Host '输入 A4 固定板的 UART 端口'
python .\tools\flash_numbered.py --role anchor --id A4 --port $anchorPort
```

```powershell
$anchorPort = Read-Host '输入 A5 固定板的 UART 端口'
python .\tools\flash_numbered.py --role anchor --id A5 --port $anchorPort
```

```powershell
$anchorPort = Read-Host '输入 A6 固定板的 UART 端口'
python .\tools\flash_numbered.py --role anchor --id A6 --port $anchorPort
```

每次都核对 ANCHOR_READY 的编号、SSID 和实际 BSSID。编号脚本给每个角色/编号使用独立构建目录及 sdkconfig，
初始配置为 UART0、115200、无辅助控制台；不依赖旧 USB Serial/JTAG 的默认配置。
运行前可加 --dry-run 只查看命令，--no-monitor 可在烧录后跳过监视器。

## 配套 TAG：本次是按编号选择一条链路

现有 TAG 的工作方式是关联一个 AP 后反复 FTM，不能因六个 Anchor 改名就自动测量六条链路。
新配套版本支持显式选择 A1–A6 中的一块，并在每轮输出编号和实际 BSSID。
例如现在要测 A1，TAG 接原来的 UART COM11：

```powershell
python .\tools\flash_numbered.py --role tag --id A1 --port COM11
```

在监视器确认：

```text
TARGET_READY,anchor_id=A1,ssid=RTT_CIR_A1,bssid=实际MAC,channel=6
LINK_ID,轮号,时间微秒,A1,实际MAC,6
```

按 Ctrl+] 退出后，用更新的采集器记录一段已实际量好距离的数据，例如真正摆在 2 m 时：

```powershell
python .\tools\record_serial_2min.py --port COM11 --condition LOS --distance-m 2 --trial A1_LOS_2m_R1 --seconds 120
```

这次除了原来的 FTM/CSI 文件，新增 round_links.csv：round_id、t_us、anchor_id、bssid、channel。
用 round_id 与同次采集内的 ftm.csv、csi*.csv 关联，即可追溯来源。
不同文件夹不能只按 round_id 合并；重启后轮号可能重新开始，必须同时保留采集标识。
旧固件没有 LINK_ID 时该表仅有表头，不会擅自为旧数据添加 A1–A6 身份。
若要验证 A2 的单链路，把 TAG 的 --id 改为 A2 后重新烧录；A3–A6 同理。

**本包尚未实现单 TAG 对六块 Anchor 自动轮询。**正式多 Anchor Ground Truth 采集还需要 TAG 的
扫描/切换/超时/scan_id/逐链路时间戳及上位机多链路记录改造。当前版本适合完成编号、逐板连通检查和单链路采集。

## 旧数据和拟合模型

重新烧录不会改变已保存的原始数据，可以继续拟合。A/B 是采集批次，不是 Anchor A1/A2。
原数据里的实际 BSSID 为 02:10:5b:f5:6c:ee；只有核对实物后，才能确认它后来被贴成 A1–A6 中的哪一个。
保持天线、带宽、信道、FTM offset 等设置有助于对照，但六块不同板之间仍需检查各自的距离偏差。
不能把一个板对的训练误差直接当成六块板的测距精度。

新八距离模型和论文图表在另附的 Single_Link_Paper_20261021.zip。
工具包根目录 models/ 仍是之前三距离的历史演示模型；不要用它代替本次八距离模型。

本环境完成主机端校验和源代码静态检查，没有 ESP-IDF/Xtensa 工具链，未生成可宣称已在板上验证的固件二进制。
实际编译和启动结果以你电脑上的 build 与上面的启动输出为准。
